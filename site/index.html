01

先建立判断

最值得带走的三个设计

事件记忆

按过以后，目标就变了

按钮释放后，几何位置可能回到按压前，但任务进度已经不同。SO101 用事件状态保存这段历史，Actor 与 Critic 都能读到阶段。

阅读 SO101 按键实现 →
奖励覆盖

后段可以覆盖前段奖励

ManiSkill StackCube 抓住后改为放置奖励，叠好后改为松手和静止奖励。代码按条件覆盖 reward，无需锁存式 FSM。

阅读 StackCube 分段公式 →
物理验收

高奖励还需要完整验收

插入、开启和抬升的成功条件各不相同。上游任务往往没有“返回初态并停稳”要求，复用奖励时要保留自己任务的终点定义。

02

从按钮理解分阶段策略

一个 Actor，按事件切换目标

这里用 X5 按钮任务的三个策略阶段解释设计。阶段来自物理事件；one-hot 是输入给策略的阶段编码。阶段编号本身不判定任务成功。

100
Actor + Critic 的阶段输入
图像 / 本体＋ 阶段 / 上下文→ 策略 → 动作
PRESS_VALID

接近目标，形成连续有效按压

只激活当前按压目标的进度项。按钮真实行程达到阈值并连续保持，才完成本阶段。

推进到下一阶段的事件

真实深度 ≥ 5 mm，连续保持 100 ms。

奖励语义

本阶段的有符号进度 + 一次性有效按压事件奖励。

以上是本地设计解释，依据调查中的奖励分段与复用边界。验收按独立物理事件检查；碰撞、重复按压和超行程仍会失败。

术语速查：Actor、Critic、FSM、one-hot 与 rollout
Actor
读取观测并输出机器人动作的策略网络。
Critic
估计状态价值，帮助 PPO 判断动作带来的回报是否好于预期；可以有明确声明的额外输入。
FSM
有限状态机。在这里根据真实事件更新任务阶段，并保存“已完成有效按压”等历史。
one-hot
只有当前阶段为 1、其余为 0 的向量。三阶段分别是 [1,0,0]、[0,1,0]、[0,0,1]。
rollout
优化策略前采集的一段轨迹。SB3 中每轮样本数通常为环境数 × 每环境采样步数。
Return
用于学习的累计回报；其数值依赖奖励定义，不能直接替代完整成功率。

04

奖励设计的四种机制

先区分“激活条件”和“计算方式”

ManiSkill · 条件覆盖

每步选择当前目标

抓住前：接近物块
抓住后：放置目标
叠好后：松手 + 物块静止

当前物理状态决定 reward 分支，后段覆盖前段。状态可以回退，通常不记录“曾经做过”。

精确系数与源码 →
SO101 · 事件门控

只有当前阶段领取进度

r_progress = clip(
  (d_previous − d_current) / scale,
  −1, 1)
切换目标 / 阶段的当步：进度为 0

接近和撤离采用各自的距离定义。一次性事件奖励单独记账，避免重复触发。

三个事件状态与奖励 →
Playground · 历史最高分

只奖励新取得的进展

r = max(S_current − M_previous, 0)
M = max(S_current, M_previous)

同一回合中，再次到达旧高度不会重复领分。退步本身不扣分，与有符号进度不同。

初态和奖励的完整条件 →
PBRS · 势函数塑形

折扣和终止边界也在公式里

F(s, s′) = γΦ(s′) − Φ(s)
若 Φ = −D：F = D(s) − γD(s′)

普通距离差没有右侧的 γ。策略不变性有条件，不能直接套到任意阶段奖励上。

数学区别与原论文 →
复制权重前，先检查时间单位

Isaac Lab manager 路径还会乘控制周期 dt，Direct 路径则按任务实现。相同 weight 并不等于相同每步奖励。任务成功、终止和重复事件也要一起检查。
